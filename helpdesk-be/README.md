# helpdesk-be

Novel HELPDESK のバックエンド（FastAPI + SQLAlchemy + MySQL）。

セットアップとコマンドはリポジトリ直下の [README.md](../README.md) を参照してください。

## ディレクトリ構成

```
app/
├── api/v1/     # エンドポイント（ルーター）
├── core/       # 設定（環境変数）と DB 接続
├── models/     # SQLAlchemy のモデル（テーブル定義）
├── schemas/    # Pydantic のスキーマ（リクエスト・レスポンスの型）
├── services/   # 業務ロジック
├── domain/     # ドメインの定義（ステータスなど）
└── main.py     # FastAPI アプリの起点
alembic/        # マイグレーション
scripts/        # 開発用のスクリプト（テストユーザーの作成など。本番用イメージには含めない）
tests/          # pytest のテスト
```

## API 一覧

ベース URL は `http://localhost:8000/api/v1` です。詳しい仕様は Swagger UI（http://localhost:8000/docs）で確認できます（`.env` で `ENABLE_API_DOCS=true` のときだけ表示。本番では表示しない）。

| メソッド | パス | 内容 | ログイン |
|---|---|---|---|
| GET | `/health` | API が起動しているかの確認 | 不要 |
| GET | `/health/db` | DB に接続できるかの確認 | 不要 |
| POST | `/auth/login` | メールアドレスとパスワードでログインする | 不要 |
| POST | `/auth/logout` | ログアウトする（そのユーザーのすべての端末のログインが切れる） | 不要（ログインしていなくても 204） |
| GET | `/auth/me` | ログイン中のユーザーを返す | 必要 |
| GET | `/tickets` | チケットの一覧を、質問日の新しい順に返す（社員には、自分のチケットと公開のチケットだけ） | 必要 |

### チケット一覧の仕組み

- 返すのは一覧に表示する項目だけ（ID・タイトル・公開設定・ステータス・質問日・質問者名・担当者名）。詳細の本文やメールアドレスは返さない
- 見える範囲は BE で決める（`app/services/ticket.py` の `visible_ticket_condition`）。画面で隠すだけにはしない
  - 社員：自分が質問者のチケットと、公開のチケット。他人の非公開チケットは一覧に含めない
  - サポート担当・管理者：非公開を含めてすべて
  - ロールが増えたときに見えすぎないよう、すべてを見られるロールを列挙し、それ以外は社員と同じ扱いにする
- 並び順は質問日（作成日時）の新しい順。同じ日時なら ID の大きい順（作成日時は秒未満まで保存する）
- ステータスは英字の値で返す（`new`：新規質問、`assigned`：担当者割り当て済み、`in_progress`：対応中、`resolved`：解決済み、`closed`：クローズ）。日本語の表記は画面で付ける
- 質問日は UTC で返す（例：`2026-03-02T06:30:00.123456Z`。秒未満はいつも 6 桁）。画面で日本時間に変える
- 担当者がいないときは `assignee_name` が `null`
- 質問者や担当者が利用停止になっても、チケットと表示名はそのまま返す
- ページ分けはしていない（すべてのチケットを返す）。件数が増えたら、ページ分けを入れる
- 応答には `Cache-Control: no-store` を付け、ブラウザなどに保存させない

### ログインの仕組み

- ログインに成功すると、JWT（ログインの証明書）を Cookie に保存する
  - 名前は、HTTPS（`COOKIE_SECURE=true`）では `__Host-access_token`、開発環境（http）では `access_token`。`__Host-` を付けると、同じドメインの別のサブドメインなどから上書きされない
  - `HttpOnly`：JavaScript から読めない（画面に悪意のあるスクリプトが入っても盗まれない）
  - `SameSite=Strict`：他のサイトからのリクエストには付かない（なりすまし操作＝CSRF の対策）
  - `Secure`：HTTPS の通信でだけ送る（既定。開発環境だけ `.env` の `COOKIE_SECURE=false` で外す）
  - 有効期限を付けないため、ブラウザを閉じると消えてログインが切れる
- JWT 自体の有効期限は 8 時間（`JWT_EXPIRE_MINUTES` で変更できる）。ブラウザを開いたままでも、期限が来ればログインが切れる
- 次の場合はすべて同じメッセージ（「メールアドレスまたはパスワードが正しくありません」）の 401 を返す。どれに当たるかは返さない（登録済みのメールアドレスを推測させないため）
  - メールアドレスが登録されていない
  - パスワードが間違っている
  - 利用停止中のユーザー
- メールアドレスは小文字で保存し、ログインでも入力を小文字にそろえて照合する（大文字・小文字を区別しない）
- パスワードの決まり：8〜20 文字で、数字と大文字（A〜Z）を必ず含む（`app/domain/password_policy.py`）
  - アカウントを作るとき（今は `make seed`）に確認する
  - ログインでは、20 文字を超えたものだけを 422 にし、それ以外は照合の結果で判断する（ログインの画面で、パスワードの決まりを明かさないため）
- パスワードはそのまま保存せず、ハッシュ（Argon2）だけを保存する
- 同じメールアドレスで 15 分以内に 5 回ログインに失敗すると、15 分間ログインできなくなる（総当たり攻撃の対策。回数と時間は `LOGIN_MAX_FAILED_ATTEMPTS`・`LOGIN_LOCK_MINUTES` で変更できる）
  - 試行は `login_attempts` テーブルに記録する。登録されていないメールアドレスも同じように記録・ロックする（処理をそろえ、応答の時間やロックの有無から、登録済みのメールアドレスを推測させないため）
  - パスワードを照合する前に、行に鍵をかけて試行を 1 回として数える。同時にリクエストを送られても、照合に進めるのは 15 分ごとに 5 回まで
  - ロック中や、5 回分の照合がすでに進んでいるときは、照合せずに断る（攻撃を受けたときの負荷を減らす）
  - ロック中も、ほかの失敗と同じメッセージの 401 を返す
  - ログインに成功すると、そのメールアドレスの記録を消す
  - 未登録のメールアドレスの記録は自動では消えない（古い記録の削除は、今後の課題）
  - 他人のメールアドレスでわざと失敗を重ねると、その人を一時的にログインできなくできる（この方式の欠点）。解除はロックの期限を待つ（管理者が解除する機能は、アカウント管理の作業で作る）
- ログインの失敗とロックは、ログに記録する（`app.auth`。メールアドレスと IP アドレス。パスワードは記録しない）
- ログインに失敗したときは、前にログインしていたユーザーの Cookie も消す
- パスワードの照合（Argon2。1 回で約 64MB のメモリを使う）は同時に 4 つまで（`PASSWORD_HASH_CONCURRENCY`）。順番待ちが 5 秒を超えたら 503 を返す（大量のログインでメモリを使い切って止まらないように）。照合の間は DB の接続を手放す（順番待ちで接続を使い切らないように）
- メールアドレスは、名前付きの形（`名前 <aaa@example.com>`）や前後の空白があると 422 にする
- ログアウトすると、そのユーザーの世代番号（`users.token_version`）が上がり、それより前に発行したトークンはすべて使えなくなる（ほかの端末のログインも切れる）
- ログイン関係の応答には `Cache-Control: no-store` を付け、ブラウザなどに保存させない
- 日時はすべて UTC で DB に保存する（DB への接続ごとにタイムゾーンを UTC にする）
- CORS は、画面から使うメソッド（GET・POST）とヘッダー（Content-Type）だけを許可する
- 画面の URL は `CORS_ORIGINS` で設定する（JSON の形で、全体を `' '` で囲む。例：`CORS_ORIGINS='["https://helpdesk.example.com"]'`）。本番では本番の画面の URL にしないと、画面からログインできない
- すべての応答に `X-Content-Type-Options: nosniff`・`X-Frame-Options: DENY`・`Referrer-Policy: no-referrer` を付ける
- 入力の形式エラー（422）の応答には、送られた値を含めない（パスワードが通信の記録などに残らないように）
